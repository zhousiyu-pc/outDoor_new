## Context

目标小程序已经具备完整功能链路，但视觉层仍是上一版“白卡 + 青绿色”体系。`outdoor-recommendation-exploration/DESIGN.md` 已确定 quiet field guide 方向，包含米白纸张、深苔绿、赭石、轻边框、地形隐喻和低噪声信息层级。

## Goals / Non-Goals

**Goals:**

- 将探索页的视觉原则转译为微信小程序 WXML/WXSS。
- 保持现有页面路径、数据流和交互行为。
- 优先重构首页、结果、详情和反馈四条用户路径。
- 在不引入图片和依赖的情况下建立稳定视觉语言。

**Non-Goals:**

- 不复制探索页的 Web 导航、品牌名或静态 mock 内容。
- 不修改后端接口、数据库和推荐规则。
- 不重做运营后台。
- 不新增 Agent 或地图能力。

## Decisions

1. 用 `app.wxss` 建立全局纸张背景、墨色、苔绿色和基础按钮规则。
2. 首页采用情绪标题 + 条件入口 + 地形装饰的单列移动端结构；高级筛选保持原有折叠行为。
3. 结果页使用场景色块和分层事实卡，不使用真实图片，避免引入外部资源。
4. 详情页优先展示出发决策、地图点、时间表和风险，反馈作为低层级但可触达入口。
5. 仅修改 WXML/WXSS 和必要的展示字段，不修改 API/存储逻辑。

## Risks / Trade-offs

- [WXSS 不支持 Web CSS 全部能力] → 使用渐变、圆角、基础定位和伪装饰，不依赖复杂 SVG 或外部字体。
- [旧页面逻辑字段较多] → 保留原有 JS 数据模型，模板只重排已有字段。
- [探索页与小程序尺寸不同] → 以 390px 窄屏可用和微信触控尺寸为优先。

## Migration Plan

分三片执行：首页与全局 token → 结果页 → 详情与反馈页。每片完成后运行 JSON/JS/模板引用静态检查，再进入下一片。

## Open Questions

- 真实用户是否更偏好“感觉优先”还是“地点优先”仍需产品验证，本次只做视觉承载，不改变搜索逻辑。
