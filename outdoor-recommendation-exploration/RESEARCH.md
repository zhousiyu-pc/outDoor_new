# 户外推荐产品研究与方向结论

日期：2026-09-25  
状态：H5 重设计 demo 的产品研究输入，不替代正式产品需求

## 1. 研究对象

本轮观察了以下公开产品的核心信息组织方式：

| 产品 | 公开入口 | 可借鉴的产品模式 | 本轮不复制的部分 |
|---|---|---|---|
| AllTrails | [alltrails.com](https://www.alltrails.com/) | 用“附近 + 适合什么活动 + 路线卡”帮助用户从浏览进入选择；路线详情强调距离、难度、评价和地图。 | 不复制其品牌绿、地图皮肤、路线数据和卡片文案。 |
| Komoot | [komoot.com](https://www.komoot.com/) | 以“探索 / 规划 / 记录”组织户外行为，强调目的地与活动类型的组合。 | 不复制其地图与导航产品结构。 |
| Wikiloc | [wikiloc.com](https://www.wikiloc.com/) | 社区贡献驱动的路线发现，路线卡上突出活动类型、位置和用户内容。 | 首版不做社区关系、评论或上传闭环。 |
| Strava Routes | [strava.com/routes](https://www.strava.com/routes) | 用路线集合、收藏和“去哪里”降低第一次选择成本。 | 不引入运动社交与成绩体系。 |
| taste-skill | [github.com/Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill) | 先明确情绪、对比度、密度、材质和动效边界，再决定组件；强调避免默认模板感。 | 不复制仓库文本、资产或任何具体品牌风格。 |

## 2. 产品判断

现有“户外推荐”项目的价值核心不是“把所有户外路线做成目录”，而是帮助用户在有限时间内回答：

> 今天，从我所在的位置出发，哪一条路线最值得去，而且我能快速判断它是否适合现在出发？

因此首版探索把首页收敛成三个连续动作：

1. **先表达此刻想要的户外感受**：林间、看水、轻松走、带孩子。
2. **再看到带理由的推荐**：为什么适合、需要多久、信息是否可靠。
3. **最后做一个低成本动作**：查看路线或收藏，不先要求用户填复杂表单。

## 3. H5 重设计视觉方向结论

- 情绪：出发前的安静、清爽和笃定，先帮用户判断，再推动动作。
- 关键词：**quiet utility / clear choice / warm confidence**。
- 设计契约：采用本地 `design-md-style-library` 的 `apple` mobile 基线，转译为项目自己的森林绿、赭石、阳光和水色；不复制 Apple 品牌资产。
- 信息密度：首屏只保留一句话输入；结果页承载来源、理由和不确定信息；详情页再展开事实和走法。
- 信任表达：来源、更新时间和“出发前看一眼”靠近路线理由，避免把不确定的信息包装成确定事实。

## 4. H5 demo 页面假设

- 目标用户：周末临时想出门、但没有明确目的地的城市用户。
- 核心场景：深圳 / 城市周边，半天到一天的轻户外。
- 首屏：一句话输入、三个示例和一个主按钮；出发设置按需展开。
- 结果页：3 条带理由、来源和状态的路线推荐。
- 交互证据：搜索、筛选、收藏、加入路线、详情、纠错反馈。

## 5. 后续需要验证的问题

- 用户更愿意先选“场景感受”还是先输入地点。
- “适合带娃 / 轻松 / 看水”等标签是否比距离更能驱动点击。
- 推荐理由是否足以建立信任，还是需要把“信息完整度 / 来源”更前置。
- 首页是否需要地图；首版探索暂不把地图作为第一视觉，以免把选择任务变成地图浏览任务。
