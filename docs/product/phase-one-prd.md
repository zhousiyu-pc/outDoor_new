# PRD：一期可靠路线参考

日期：2026-09-24  
主导岗位：product-analyst  
状态：v1 / 本轮开发输入

## 1. 目标

一期只交付一个闭环：

```text
一句自然语言诉求
→ 多平台 / Skill 获取候选路线
→ 展示来源可靠的路线参考
→ 用户明确采纳
→ 采纳路线落地为正式路线资产
```

## 2. 用户故事

- 作为轻户外用户，我只想输入一句诉求，例如“周末带孩子找一条轻松自然步道”，系统就给我可参考路线。
- 作为用户，我需要看到每条路线来自哪里、什么时候获取、为什么匹配我。
- 作为用户，我只希望我明确采纳的路线进入系统，不希望浏览过的候选污染后续数据。
- 作为运营人员，我需要区分候选参考和正式资产，并能看到采纳来源。

## 3. 一期范围

### 3.1 用户端

- 一句自然语言诉求输入；
- 候选路线列表；
- 路线来源、采集时间、匹配理由；
- 采纳路线动作；
- 采纳后提示正式落地；
- 已采纳路线可进入详情和反馈。

### 3.2 服务端

- Java 业务服务接收小程序请求；
- Java 服务调用 Python Agent 获取候选；
- Python Agent 以受控 Skill / Connector 模拟多来源获取；
- Java 服务返回候选路线；
- Java 服务处理用户采纳；
- 采纳路线写入 MySQL 设计表，当前本地版使用文件存根以避免未授权数据库变更。

### 3.3 数据规则

- 外部平台和 Skill 返回的内容默认为候选参考；
- 未采纳候选不得成为正式路线资产；
- 用户明确点击“采纳路线”才正式落地；
- 浏览、详情查看、收藏、停留不等于采纳；
- 每条候选必须有来源依据；
- 来源不可靠或冲突时必须明确提示。

## 4. 非目标

- 不做真实平台爬取；
- 不绕过任何平台限制；
- 不做专业 GPS / 离线导航；
- 不做复杂天气、停车、厕所完整出行决策；
- 不做复杂 Agent 自主决策；
- 不做生产数据库写入；
- 不部署微信云。

## 5. 验收标准

- 输入一句诉求可以获得候选路线；
- 候选路线包含来源、来源类型、采集时间、匹配理由；
- 采纳接口可以将指定候选转为正式资产记录；
- 未采纳候选不进入正式资产；
- Java 服务和 Python Agent 均有健康检查；
- Dockerfile 可用于微信云托管方向部署准备；
- 测试文档记录本地验证命令；
- 最终状态标记为 ready_for_human_acceptance。
