# 产品一期范围：可靠路线参考

日期：2026-09-24  
主导岗位：product-analyst  
状态：v0.1 / 一期范围收敛  
上游依据：

- `product-requirements-framework.md`
- `market-research-competitor-analysis.md`
- `data-source-and-recommendation-framework.md`

## 1. 一期目标

一期只验证一个核心价值：

> 用户只需输入一句自然语言出行诉求，系统即可从多个外部来源和受控 Skill 获取、整理并提供有可靠来源依据的路线参考；只有用户明确采纳的路线，才沉淀为系统正式路线资产。

一期不是完整的户外出行助手，也不是专业导航工具。首要任务是建立用户对“路线信息可信”的基础认知。

## 2. 一期用户价值

用户能够：

1. 输入一句自然语言出行诉求；
2. 获得系统整理后的路线参考；
3. 查看路线的基本信息和来源依据；
4. 判断路线是否值得进一步了解或出发；
5. 发现信息问题时进行反馈。

一期的“推荐”重点是：

- 从可靠信息中筛选；
- 给出可理解的匹配理由；
- 明确来源和更新时间；
- 不确定时明确提示，而不是强行给出结论。

## 3. 一期产品定位

一期产品定位为：

> 面向亲子和轻户外用户的可靠路线参考工具。

与竞品的关系：

- 不与两步路、六只脚竞争专业轨迹和离线导航；
- 不与高德竞争通用地图和到达路径；
- 不与小红书竞争内容数量和传播；
- 先解决“哪些路线信息值得参考”这一基础问题。

## 4. 一期范围

### 4.1 用户要求输入

一期用户只需要输入一句自然语言诉求，例如：

- “周末带孩子找一个离市区近、轻松一点的自然步道”
- “想找适合老人和小孩的半天户外路线”
- “今天想找一条不太累、可以看水景的徒步路线”

系统负责从自然语言中理解可能的出行人群、活动类型、距离、难度、时长和路线特点。

一期不要求用户先填写复杂筛选表单；结构化筛选可以作为后续补充能力。

### 4.2 路线参考

系统根据用户一句话诉求，从多个来源获取并整理路线参考，至少包括：

- 路线名称；
- 路线基本描述；
- 与用户要求的匹配理由；
- 基本难度或适合人群信息；
- 来源；
- 来源更新时间或采集时间；
- 当前已知的不确定信息；
- 用户是否已明确采纳。

一期强调“参考”，不承诺绝对正确，也不直接替用户做安全或出行保证。

### 4.3 用户采纳与正式落地

外部平台和 Skill 获取的路线首先处于“候选参考”状态：

1. 系统向用户展示候选路线及来源依据；
2. 用户明确点击“采纳路线”或等价的确认动作；
3. 被用户采纳的路线才进入系统正式路线资产；
4. 未被采纳的候选路线不进入正式路线库；
5. 正式路线后续可以接受用户反馈、来源更新和必要治理。

“用户采纳”必须是明确动作，不能用浏览、打开详情、收藏或短暂停留推断。

### 4.4 来源可靠性

一期必须优先建立来源可靠性表达：

- 来源类型清晰；
- 来源链接或来源标识可追溯；
- 信息获取或提交时间可见；
- 用户提供和外部来源明确区分；
- 多来源不一致时提示冲突；
- 来源不足时降低推荐信心或明确标记待核验。

### 4.5 用户反馈

一期保留轻量反馈入口，用于收集：

- 路线不存在或无法进入；
- 路线信息错误；
- 路线已关闭或状态变化；
- 难度、距离等信息不准确；
- 用户补充的新线索。

反馈的目标是改进来源和路线信息，不在一期建设复杂社区。

### 4.6 信息获取与沉淀

一期主要从以下来源获取信息：

1. 经过授权或明确允许的外部平台；
2. 可审查、可追溯的 Skill / Connector；
3. 用户反馈和用户补充；
4. 必要的人工修正。

人工录入不是一期主要供给方式。外部来源和 Skill 结果先进入候选参考流程；只有用户采纳后，才进入正式路线资产沉淀和后续治理流程。

## 5. 一期不做

一期明确不做：

- 专业 GPS 轨迹记录；
- 离线地图和专业导航；
- 复杂路线规划；
- 天气、停车、厕所、路况等完整出行辅助；
- 出行计划和返程建议；
- 圈子、社交和关注关系；
- 用户路线社区；
- 商业化、装备商城和旅游预订；
- 复杂个性化推荐；
- 自动批量抓取未经授权的平台内容；
- 以人工录入作为主要数据供给；
- 复杂 Agent 自主决策；
- 全国范围路线覆盖。

## 6. 一期核心闭环

```text
用户输入一句自然语言诉求
→ 系统理解诉求并生成检索条件
→ 从多个平台和受控 Skill 获取路线信息
→ 系统整理、去重、比对和筛选
→ 返回有来源依据的候选路线参考
→ 用户查看来源、时间和匹配理由
→ 用户明确采纳路线
→ 路线正式落地到系统
→ 用户反馈错误或补充信息
→ 信息进入来源治理和路线修正
```

## 7. 一期来源策略

### P0 来源

- 多个可验证、可持续使用的外部授权或公开来源；
- 至少一种受控 Skill / Connector；
- 用户反馈和用户补充；
- 必要的人工修正。

### P1 来源

- 第二类外部信息来源；
- Skill 辅助发现、整理和去重；
- 多来源冲突识别；
- 来源质量比较。

一期不追求无限扩展来源，优先保证首批来源可用，且：

- 来源合法；
- 来源可追溯；
- 来源可重复获取或验证；
- 来源信息能支撑路线参考。

“各平台”不等于无边界抓取。每个平台必须单独确认接入方式、使用权限、访问稳定性和内容可追溯性。

## 8. 一期验收口径

一期达到以下条件，才认为核心价值成立：

1. 用户能够输入一句自然语言出行诉求；
2. 系统能够从多个平台和受控 Skill 返回候选路线参考；
3. 每条候选路线都有来源依据；
4. 来源类型和时间信息可被查看；
5. 推荐结果能够解释与用户要求的基本匹配关系；
6. 来源不足或存在冲突时，系统能够明确提示；
7. 用户明确采纳后，路线才进入系统正式路线资产；
8. 未采纳候选不污染正式路线库；
9. 用户能够反馈已采纳路线的错误或补充信息；
10. 反馈能够进入后续治理流程；
11. 不依赖复杂社交、导航、商业化或高级算法即可完成主路径。

## 9. 一期成功指标候选

以下指标用于后续产品确认，不在本文件中锁定具体数值：

- 有来源候选路线展示比例；
- 用户采纳后正式落地比例；
- 未采纳候选进入正式路线库的错误率；
- 来源可追溯比例；
- 推荐结果被用户查看详情的比例；
- 用户对路线可靠性的评价；
- 路线错误反馈率；
- 反馈处理及时性；
- 重复或冲突信息发现率；
- 用户从输入要求到获得有效路线参考的完成率。

## 10. 一期最大风险

### 10.1 来源不足

没有稳定来源时，产品会退化为人工路线录入工具。

### 10.2 来源不可靠

如果外部来源过期、复制错误或无法核验，产品会损害用户信任。

### 10.3 范围膨胀

如果一期同时加入天气、停车、导航、社交和复杂 Agent，核心价值将无法验证。

### 10.4 推荐承诺过高

一期应使用“路线参考”和“信息依据”，不应宣传为绝对安全、绝对准确或自动规划最佳路线。

## 11. 阶段结论

一期先做窄：

```text
用户要求
→ 可靠来源
→ 路线参考
→ 来源反馈
```

先证明用户愿意基于可靠来源查看和选择路线，再扩展到出行决策、动态信息、复杂推荐和 Agent 自动化。
