# 一期首页产品化 UI 重构说明

## 背景

用户反馈当前小程序首页“太混乱，没有产品感”。本次重构目标不是继续强化户外视觉氛围，而是把首页收敛为一个清晰的搜索/推荐型产品入口：用户只需要输入一句诉求，系统给出来源可靠的路线候选，用户采纳后才落地。

## 竞品入口模式观察

| 竞品/模式 | 可借鉴点 | 对本项目的转化 |
| --- | --- | --- |
| AllTrails | Explore 入口支持按位置/关键词搜索、筛选，并在详情里展示地图、评论、照片、路线信息；强调 verified/curated trails、社区评价与 trail conditions。 | 首页优先呈现“一句话输入 + 可信来源说明”，结果页再承载来源、评价、开放/停车/厕所等不确定信息。 |
| komoot | 产品围绕 Discover / Plan / Navigate；路线规划可基于运动类型、难度、距离、地形和社区推荐；近期也强调自然语言查询。 | 一期不做复杂规划器，把“Plan”前置为一句话诉求；筛选只作为补充，不抢主入口。 |
| Google Maps/高德地图类 | 首页强搜索框、当前位置和周边探索入口，装饰弱，行动路径明确。 | 顶部只保留品牌和当前城市/出发地；首屏只保留搜索面板和主 CTA。 |
| 小红书/马蜂窝内容搜索类 | 搜索框 + 热门示例词 + 内容可信线索，降低用户不知道怎么问的成本。 | 保留 5 个 prompt chip 作为“可以这样问”，但视觉权重低于输入框。 |

## DESIGN.md UI Mode Card

- UI context：微信小程序用户端首页，consumer / mobile / recommendation search。
- 选用 DESIGN.md：`wise` 作为主基线。
- 适配原因：Wise 模式强调清晰转化路径、重标题、可信金融式信息卡、柔和浅色背景和圆角白卡；适合“可靠路线来源”这一信任型推荐产品。
- 直接采用：
  - 布局节奏：单列移动端、顶部轻导航、首屏 Hero + 输入卡 + CTA。
  - 组件形态：圆角白卡、pill badge、胶囊按钮、柔和浅绿/米白背景。
  - 状态表达：可信标签、来源流程说明、输入计数、折叠筛选。
- 项目化 token：
  - Primary：`#246B4D`，更偏户外绿，不使用 Wise 品牌青柠。
  - Canvas：`#F6F8F3` / `#FFFFFF`。
  - Ink：`#111C17`。
  - Muted：`#68736D`。
  - Accent：`#D97732` 仅作少量强调。
  - Radius：主卡 `32rpx`，按钮/标签 `999rpx`。
- 不复制内容：不使用 Wise 品牌色、字体名称、品牌资产或金融话术；只转化布局与组件规则。

## 首页信息层级

1. 顶部：品牌 + 出发地/城市状态。
2. Hero：一句话价值主张，明确“可靠路线来源”。
3. 主输入：大 textarea，直接承接自然语言诉求。
4. 主按钮：帮我找路线。
5. 示例 prompt：帮助用户快速理解一句话怎么输入。
6. 出发地 / 时间：作为上下文控件，不再成为表单主体。
7. 信任卡：说明“多来源候选 / 只采纳才落地 / 不确定可反馈”。
8. 高级筛选：折叠在二级，用户需要时再展开。
9. 分享路线：备用入口，低权重。

## 用户文案原则

页面文案必须先回答用户“我能得到什么”，再解释产品“怎么做到”：

- 不对用户说：Skill、候选、入库、正式资产、数据沉淀、后台处理；
- 改为用户能理解的动作：帮你找、先看看、出处说清楚、出发前提醒、加入我的路线；
- 不把内部状态当产品价值：`采纳` 在业务层保留，但用户端优先表达为“加入我的路线”；
- 不使用技术流程解释作为主标题，来源可靠性放在简短说明和路线详情中；
- 主按钮表达结果，不表达系统动作：使用“帮我找路线”，而不是“提交查询”或“获取候选”。

### 关键文案映射

| 内部语言 | 用户端表达 |
| --- | --- |
| 多平台 / Skill 获取候选 | 从多个地方帮你找 |
| 候选参考 | 参考路线 |
| 采纳路线 | 加入我的路线 |
| 正式落地到系统 | 加入你的路线清单 |
| 不确定性提示 | 出发前要留意 |
| 补充筛选 | 再补充一点偏好 |
| 分享路线线索 | 分享你去过的好地方 |

## 旧风格污染清理

必须移除或弱化：

- 大山水插画、太阳、山丘等装饰；
- FIELD GUIDE 编号式文案；
- 天气贴纸；
- 多段大标题堆叠；
- 复杂 order override；
- 高级筛选在首屏抢主路径。

## 验收要点

- 首屏一眼能看出“输入一句话找路线”。
- 主输入和主按钮是最大视觉焦点。
- 出发地/时间只是上下文，不像必填表单。
- 页面没有大面积装饰图抢注意力。
- 用户能理解路线不会自动入库，只有采纳后才落地。
